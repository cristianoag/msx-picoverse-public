# Change Log

## PicoVerse 2350 Carnivore2 v1.0

- Added the dedicated Carnivore2 firmware (`2350/software/carnivore2.pio`), following the layout of the other firmwares (`pico/carnivore2` firmware, `tool` UF2 creator, `tests`, `docs/log.md`, top-level `Makefile`) for issue #102 of the public repository.
- `pico/carnivore2/core/c2_core.[ch]`: portable software model of the Carnivore2 FPGA (`mcscc.vhd` 2.50): expanded slot and sub-slot decode (`Mconf`, `SLM_cfg`, `0xFFFF`), the 64-byte register window with its four possible bases, bank windows R1–R4 with page registers and delayed reconfiguration (`CardMDR[3:2]`), `DatM0` direct vector port, 1 MB memory mapper (ports `FC–FF`, `3C` and memory-mapped registers), Sunrise IDE window and ROM segments, FM-PAC slot (ROM page, 8 KB SRAM keys, OPLL ports), SCC/SCC+ window and bank/mode registers including the NSC SCC+ write rules, PSG/beeper ports with `PsgAlt`, port `#F0` protocol with `PFXN`, volume registers. VHDL quirks that software may depend on are kept.
- `pico/carnivore2/core/c2_flash.[ch]`: M29W640GB command model (autoselect, CFI, byte/double/quad byte program, unlock bypass, block and chip erase).
- `pico/carnivore2/core/c2_eeprom.[ch]`: 128-byte Microwire configuration EEPROM behind `CardMDR+0x23`.
- `pico/carnivore2/storage/c2_store.[ch]`: the 8 MB FlashROM lives in RP2350 flash at offset 4 MB; program/erase go to a 6 MB PSRAM write-back cache of 4 KB sectors that is committed to flash when the MSX is quiet. The mapper and MegaRAM/shadow RAM use the first 2 MB of PSRAM; the EEPROM is stored in the last flash sector.
- `pico/carnivore2/audio/c2_audio.[ch]`: SCC/SCC+ (emu2212), FM-PAC (emu2413, stereo/mono), PSG mirror (emu2149) and beeper mixed with the `mv16` volume curve, rendered on core 1 from a lock-free register queue.
- `pico/carnivore2/carnivore2.c`: PSRAM/PIO0/PIO1 setup at 210 MHz, cold-boot restart handshake, core 0 bus loop, core 1 microSD IDE back-end. IDE and microSD code is copied from LoadROM.
- `tool/src/carnivore2.c`: `carnivore2.exe` creates the UF2 (`-f` installs a Carnivore2 FlashROM image at flash offset 4 MB; without it only the firmware is updated and the stored FlashROM is kept).
- `tests/c2_core_test.c`: 156 host checks for the register model, bank windows, mapper, flash chip, IDE, FM-PAC, SCC, PSG ports and EEPROM (`make test`).
- Docs: added `docs/msx-picoverse-2350-carnivore2.md`, linked it from the public readme, and added the Carnivore2 documentation and software folder to `build/Makefile` packaging.
- Fixed C2MAN "Write Boot Menu" (9, 4) and chip erase hanging: the flash model wrongly protected the two bottom boot blocks while `ConfFl[0]=0` (its power-on value), so the erase/program of 0x0000–0x3FFF was ignored and C2MAN's data-polling loop never finished. The boot blocks are now ordinary blocks (`c2_flash.[ch]`).
- Block and chip erase are now instant markers (`C2S_ERASED` in the sector map, reads return `0xFF`); the flash erase of those sectors is done by the background commit (`c2_store.c`), instead of copying and committing every sector synchronously, which would have stalled the MSX for minutes on a chip erase. Host tests cover boot-block erase/program and chip erase (162 checks).
- Performance: games ran slow because every cartridge read took about 1.5 µs of /WAIT (full decode, double FIFO polling, XIP code fetches shared with core 1). Added a per-8 KB-page read decode cache in the core (`c2_fast_get`/`c2_fast_rebuild`): pages without register/SCC/IDE/FM-PAC special addresses reduce to a plain FlashROM or RAM read at `base + offset`, and the cache is invalidated by any write that changes the decode (bank/page registers, `CardMDR` and the register window, sub-slot register, SCC bank/mode, mapper ports, port `3C`, FM-PAC page/keys, IDE control, port `#F0` commands). Host tests check that the fast decode matches the full decode for all 65,536 addresses in several configurations (868k checks).
- The bus loop reads the PIO FIFO status once per iteration, drains pending writes and I/O only when a read is waiting (and after it was seen, so a bank switch immediately before a read is never missed), and answers fast-path reads without function calls.
- The firmware was built `copy_to_ram` (`pico_set_binary_type`; reverted later, see below), so core 1 (SCC/FM/PSG rendering) no longer competes with the bus loop on the XIP cache. `C2_SYS_CLOCK_KHZ` (default 210 MHz, same as Explorer/LoadROM) is the single knob for the system clock.
- Added a 128 KB SRAM read cache for the FlashROM image (`C2S_CACHE_KB`, 512-byte direct-mapped blocks filled from XIP on first read, invalidated when a sector is committed or erased). Copying ROMs to PSRAM was not done on purpose: PSRAM sits behind the same QMI/XIP cache as the flash and is clocked slower, so it cannot be faster; on-chip SRAM is. Sectors with pending writes bypass the cache.
- The slot reported by port `#F0` `S` is now derived lazily from the last accessed page (`last_page`) instead of being computed on every read, and the FlashROM chip mode (autoselect/CFI/reset) is folded into the page decode cache (`c2_set_flash_array`), which removes two checks from the read path.
- Space Manbow showed a one-line artifact at the top of the screen: the raster interrupt code that runs from the cartridge was still finishing too late because every cartridge read held /WAIT for longer than one Z80 clock. The system clock is now 300 MHz (C2_SYS_CLOCK_KHZ, same clock and flash/PSRAM QMI timings as the OPL4 firmware; -DC2_SYS_CLOCK_KHZ=210000 restores the old setting), and the SRAM read cache is 192 KB (C2S_CACHE_KB, any multiple of 512 bytes; the map showed about 127 KB of free SRAM at 128 KB cache).
- Start-up on real MSX computers: a Panasonic FS-A1FX (turbo R) mostly fell into BASIC while the FPGA MSX started the cartridge. Tested on both: the `copy_to_ram` image (default until now) works on the FPGA only; holding `/WAIT` from the first instruction of `main()` broke both (that experiment was removed); running the firmware from flash instead (`C2_COPY_TO_RAM=OFF`) works on both, and at good speed. `copy_to_ram` made `main()` start later because the whole image had to be copied to SRAM first, so the FS-A1FX BIOS scanned the slots before the cartridge answered. The default is now the flash image; `make C2_COPY_TO_RAM=ON` restores the SRAM image and `make C2_CLOCK_KHZ=210000` selects the old clock (variables, not `-D`, which GNU make treats as its own debug switch). The `firmware` target reconfigures CMake on every run so the options always apply. The bus path, the Carnivore2 core and the ROM cache stay in RAM (`C2_RAM_FUNCS` / `__not_in_flash_func`), so read latency does not depend on this.
- Added `tool/make-flash-image.ps1` to build a FlashROM image for `carnivore2.exe -f` from the RBSC `BOOTCMFC.BIN`, `BIDECMFC.BIN` and `FMPCCMFC.BIN` (boot menu as four 8 KB pieces at `0x0000/0x2000/0xC000/0xE000`, IDE BIOS at `0x010000`, FM-PAC BIOS at `0x030000`, default configuration record at `0x4000`). The layout was derived by comparing with the factory `Carnivore2.rom`; the generated image differs from it in one byte (`0x03FFED`, FM-PAC BIOS). The documentation lists the ways to get an image (factory file, this script, a `C2BACKUP` dump).
- Not yet validated: the firmware has not been built on the RP2350 toolchain in this session and not tested on hardware or against a physical Carnivore2. The slave-slot features of the original design need `/MERQ`/`/M1`, which the cartridge does not provide, and are not modelled.
