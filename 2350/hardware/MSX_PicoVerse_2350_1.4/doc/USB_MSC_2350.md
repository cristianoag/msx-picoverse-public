# USB 매스스토리지 인식 불가 원인 분석 — MSX PicoVerse 2350

작성 2026-09-10 / **개정 2026-09-19 (rev 1.4 반영)** / 펌웨어 `explorer.pio`

> **결론은 rev 1.4 에서 하드웨어로 해결되었다.** D2 삭제 + SW1/Q3/Q4/R40/C12 삭제.
> 적용 결과와 그에 따르는 운용 규칙은 **§11** 에 있다.
> §1~§10 은 원인 규명 과정의 기록이며 rev 1.3 기준으로 읽으면 된다.

---

## 1. 증상

| 항목 | 상태 |
|---|---|
| USB-C로 U1(RP2350) UF2 업로드 | 정상 |
| MSX 장착 후 USB 메모리(카드리더 + microSD 16G, FAT16 ×4) 인식 | **실패** |
| 동일 매체 2040 버전 | 정상 (전언) |

---

## 2. 결론

**J5(USB-C)의 VBUS에 전원을 공급하는 경로가 보드에 없다.**
MSX에 꽂힌 상태에서 J5 VBUS는 0 V이므로, 버스 전원으로 동작하는 USB 메모리는
enumeration 이전에 아예 켜지지 않는다. 펌웨어 문제도 파일시스템 문제도 아니다.

---

## 3. 근거 — 넷리스트

### 3.1 rev 1.3의 VBUS 넷 구성원 전부

```
/VBUS   :  J5.A4  J5.A9  J5.B4  J5.B9   C27.2  C28.2  Q3.2  D2.2
```

소스가 없다. 커넥터 4핀 + 벌크 커패시터 2개 + Q3(DTC114EUA) 베이스 + D2 뿐이다.

### 3.2 D2 방향

```
D2  B5819WS :  pin1 = K(캐소드) → Net-(D2-C) → F1 → +5V
               pin2 = A(애노드) → /VBUS
```

KiCad `Device:D` 심볼 규약대로 pin1 = K, pin2 = A이고, 넷 자동명이 `Net-(D2-C…)`인
것이 이를 확정한다. 즉 **VBUS → 보드 단방향**이다. +5V 레일에서 VBUS로 나가는
역방향 경로는 존재하지 않는다.

### 3.3 +5V 레일 오링 구조 (참고)

```
USB 측 :  J5.VBUS ──D2──►── F1(FSMD075) ──┐
                                          ├── +5V ── U1.34(VBUS 핀)
MSX 측 :  J11.45/47(+5V_MSX) ──Q2(P-MOS)──┘   (Q1 DMMT5401 = 이상 다이오드 제어)
```

`U1.34`는 Core2350B의 **VBUS 핀**이며 `+5V`에 물려 있다. 즉 모듈은 MSX 5 V로
정상 급전된다. 그러나 이 `+5V`는 D2 때문에 **J5 커넥터로 되돌아 나가지 못한다.**

### 3.4 2040 보드와의 대조 — 이것이 2040/2350 차이의 실체

2040 rev 1.3 BOM 전체:

```
C1 0.1u, C2 10u, R1 2K, R2~R13 10K, D1 1N5819(SOD-123),
Q1~Q5 BSS138, U1 RP2040-PURPLE
```

**USB 커넥터가 BOM에 없다.** 2040 보드에는 독립 USB 커넥터가 없고,
외부로 노출되는 USB 포트는 **RP2040-Purple 모듈 자신의 USB-C**다.
그 모듈의 5V(VBUS) 핀은 자기 커넥터 VBUS와 직결이고, 보드는 MSX +5V를
D1(1N5819) 하나만 거쳐 그 핀에 넣는다.

```
2040 :  MSX +5V ──D1──► 모듈 5V핀 ≡ 모듈 USB-C VBUS  →  펜드라이브 급전 O
2350 :  MSX +5V ─────► U1.34(모듈 VBUS 핀)   … 모듈 자체 커넥터에만 유효
        J5.VBUS ◄──D2── (역방향 차단)          →  J5에 꽂은 장치 급전 X
```

2040은 "모듈 커넥터 = 외부 포트"라서 우연히 호스트 급전이 성립했고,
2350은 외부 포트가 별도의 J5(보드 x=45, 우측 엣지)라서 성립하지 않는다.

### 3.5 CC 저항

```
R55 5.1k : J5.CC1 → GND
R56 5.1k : J5.CC2 → GND
```

Rd 고정. 이 포트는 전기적으로 **UFP(싱크) 전용**으로 배선되어 있다.
USB2 데이터(D+/D-)에는 영향이 없으므로 CC는 이번 증상의 직접 원인은 아니지만,
"이 포트는 소스가 될 의도로 설계되지 않았다"는 사실을 뒷받침한다.

## 4. 확인 방법 (1분)

1. 카트리지를 MSX에 꽂고 전원 ON, Nextor USB 모드로 진입
2. J5의 VBUS 핀(A4/A9/B4/B9) 또는 **D2 pin2**와 GND 사이 전압 측정
   - **0 V → 본 문서의 결론 확정**
   - 4.4 V 이상 → 다른 원인. 5절로

보조 확인: 셸을 열고 Core2350B **모듈 자체의 USB-C**에 펜드라이브를 꽂으면
(모듈에 커넥터가 있는 경우) 그쪽 VBUS는 `+5V`와 직결이므로 인식되어야 한다.
인식되면 원인이 J5 급전 부재임이 이중으로 확정된다.

## 5. 소프트웨어 측 점검 — 2차 원인 후보

하드웨어가 아니라면 아래 순서로 본다. 코드 자체에는 결함이 없다.

### 5.1 빌드 모드가 USB인지

`explorer.c`

```c
#define MAPPER_SUNRISE_USB        10
#define MAPPER_SUNRISE_MAPPER_USB 11
#define MAPPER_SUNRISE_SD         15
#define MAPPER_SUNRISE_MAPPER_SD  16
```

USB 백엔드는 mapper 10/11에서만 `sunrise_usb_task`가 core1에 올라간다.
15/16이면 `sunrise_sd_task`가 올라가고 **USB는 아예 초기화되지 않는다.**

- `loadrom.exe -s2 / -m2 / -c2 / -r2` = USB
- `loadrom.exe -s1 / -m1 / -c1 / -r1` = microSD
- Explorer 메뉴에서는 "Sunrise Nextor **USB**" SYSTEM 엔트리를 골라야 한다

`-s1` 빌드를 올려놓고 USB 메모리를 꽂았다면 당연히 아무 일도 일어나지 않는다.
**가장 먼저 확인할 것.**

### 5.2 TinyUSB 호스트 빌드 여부

`CMakeLists.txt`

```cmake
set(EXPLORER_USB_STDIO_DEBUG 0)      # ← 반드시 0
...
if (NOT EXPLORER_USB_STDIO_DEBUG)
    list(APPEND EXPLORER_SOURCES ${PICO_SDK_PATH}/lib/tinyusb/src/tusb.c)
    target_link_libraries(explorer tinyusb_host)
endif()
```

`EXPLORER_USB_STDIO_DEBUG`가 1이면 `CFG_TUSB_RHPORT0_MODE`가 `OPT_MODE_DEVICE`가
되고 `sunrise_usb_task()`는 `while(1) sleep_ms(1000)` 스텁으로 대체된다.
현재 리포지토리 값은 0이므로 정상이다.

`tusb_config.h`도 정상: `CFG_TUSB_RHPORT0_MODE = OPT_MODE_HOST`, `CFG_TUH_MSC = 1`,
`CFG_TUH_HUB = 1`. 2040 쪽 설정과 실질적으로 동일하다.

### 5.3 LUN 0 고정

`sunrise_ide.c`

```c
void tuh_msc_mount_cb(uint8_t dev_addr)
{
    current_dev_addr = dev_addr;
    current_lun = 0;                       // ← LUN 0 고정
    usb_device_mounted = false;
    tuh_msc_inquiry(dev_addr, 0, &inquiry_resp, inquiry_complete_cb, 0);
}
```

**멀티슬롯 카드리더**(SD + CF + MS 등)는 LUN을 3~4개 보고하며 microSD가
LUN 0이 아닐 수 있다. 이 경우 코드는 빈 슬롯을 물고 실패한다.
지금 쓰는 것이 단일 슬롯 리더면 무관하지만, **일반 USB 펜드라이브로 한 번
교차 시험**하는 편이 원인 분리에 훨씬 낫다. 소비전류도 리더보다 작다.

## 6. 파일시스템 / 용량은 원인이 아니다

| 사용자 구성 | 지원 여부 |
|---|---|
| FAT16 | 지원 (Sunrise Nextor의 정식 요구사항) |
| 파티션 4개 | 지원 (MBR 프라이머리 4개까지) |
| 파티션당 최대 크기 | 4 GB까지 |
| 16 GB 매체 | 무관 — Nextor는 파티션 단위로 접근 |
| 섹터 크기 | 512 표준. 코드는 4 K 네이티브도 읽기 지원(`usb_read_buffer[4096]`) |

참고로 4 K 네이티브 섹터 장치는 **쓰기가 에러로 반환**된다(read-modify-write 미구현).
카드리더는 512를 보고하므로 해당 없음.

## 7. rev 1.3 응급 개조 (지금 당장 쓰려면)

### 7.1 최소 개조 — D2 패드 위에 역방향 쇼트키 1개

D2 패드에 **B5819WS(또는 BAT54) 한 개를 D2와 반대 방향으로 겹쳐 실장**한다.

```
기존 : /VBUS ──[A  D2  K]── mid ──[F1]── +5V     (USB → 보드)
추가 : /VBUS ──[K  Dx  A]── mid                  (보드 → USB)
```

- 추가 다이오드의 **캐소드가 D2 pin2(VBUS) 쪽**, 애노드가 D2 pin1(mid) 쪽
- mid 노드를 쓰므로 **F1(FSMD075, 0.75 A)의 과전류 보호가 유출 경로에도 그대로 적용**된다
- PC 연결 시: VBUS 5.0 V > mid(≈4.6 V) → 추가 다이오드 역바이어스 → **역급전 없음**
- MSX 동작 시: +5V(≈4.9) → F1 → Dx(≈0.35 V @300 mA) → **VBUS ≈ 4.5 V**

USB 규격 하한(4.4 V)에 가깝다. 대부분의 펜드라이브는 내부 LDO 드롭아웃이
낮아 동작하지만, MSX 5 V가 처지는 기기에서는 불안정할 수 있다.

### 7.2 드롭이 문제되면 — P-MOS 우회

`SSM3J332R`(이미 BOM에 Q2/Q4로 존재) 소스=mid, 드레인=VBUS, 게이트=GND(10 k 경유),
게이트–소스에 100 k 풀업. Rds(on) 수십 mΩ이므로 VBUS ≈ 4.85 V.
단, 상시 ON이므로 **PC 연결 시 역급전**이 생긴다. PC와 동시 사용하지 않는다는
전제에서만 쓸 것. 상시 안전을 원하면 8절.

### 7.3 D2를 0 Ω으로 치환하는 안 — 권장하지 않음

가장 간단해 보이지만 **역급전이 실제로 발생한다.**

#### 왜 발생하는가

Q1/Q2 오링은 `+5V → +5V_MSX` 방향만 막는다(P-MOS 바디다이오드 애노드가 `+5V_MSX`,
Q1 DMMT5401 정합쌍이 `+5V > +5V_MSX`일 때 게이트를 닫음).
**`+5V_MSX → +5V` 방향은 정상 도통 경로**이고, D2가 0 Ω이 되면 그 뒤가 그대로

```
+5V_MSX ──Q2(ON)── +5V ──F1(0.25Ω)── 0Ω ── /VBUS ── PC USB 포트
```

로 이어진다. 두 5 V 소스가 **가드밴드 없이 하드 병렬**이 되므로,
그 순간 높은 쪽이 낮은 쪽으로 흘려보낸다. MSX 슬롯 5 V는 4.9~5.15 V,
PC VBUS는 4.75~5.25 V로 서로 겹치는 범위라 어느 쪽이 이길지는 기기마다 다르다.

#### 실제로 문제되는 시나리오

| 상황 | 결과 |
|---|---|
| PC 켜짐 + MSX 켜짐, MSX 쪽이 높음 | MSX 5 V가 PC VBUS로 유출. USB 규격 §7.2.1 위반 |
| **PC 꺼짐/절전 + 카트리지 MSX 장착** | MSX 5 V가 PC의 5 V 스탠바이 레일을 **백피드**. 가장 위험 |
| PC 포트에 역전류 검출 기능이 있는 경우 | 포트 파워스위치가 OC/역전류로 래치 오프. USB 포트가 죽은 것처럼 보임 |
| PC만 연결 (MSX 미장착) | 문제 없음 — Q2 바디다이오드가 MSX 방향을 막는다 |

전류는 F1(FSMD075, hold 0.75 A / trip 1.5 A)로 제한되므로 소손 위험은 낮지만,
"규격 위반 + 상대 PC 포트를 죽일 수 있음"은 남는다.

#### 쇼트키가 안전한 이유 — 순방향 강하가 곧 가드밴드

7.1의 역방향 쇼트키는 **Vf ≈ 0.3 V만큼의 데드밴드**를 만든다.

```
MSX만  : mid 4.98 → Dx 도통 → VBUS ≈ 4.55 V              (급전 O)
PC 연결: mid 4.7 (D2 강하 후) vs VBUS 5.0 → Dx 역바이어스  (유출 X)
동시   : mid 4.98 vs VBUS 5.0 → 순방향 0.02 V, 임계 이하   (유출 무시 가능)
```

0 Ω은 이 0.3 V가 0이 되는 것이고, 그래서 막을 수단이 사라진다.
**드롭 0.3 V를 아끼려다 역급전을 얻는 교환이므로 하지 말 것.**

#### 운용 규율로 회피하는 안 — 개인 테스트기 한정으로는 성립

"MSX 장착 중에는 PC에 USB를 연결하지 않는다"를 지키면 전기적으로 문제 없다.
경우의 수는 넷뿐이고 위험한 것은 하나다.

| 조합 | 결과 |
|---|---|
| MSX ON + PC 미연결 | 안전 (의도한 동작) |
| 카트리지 미장착 + PC 연결 | 안전 — Q2 바디다이오드가 PC→MSX를 막는다 |
| MSX 장착·전원 OFF + PC 연결 | 안전 — `+5V_MSX` = 0 V, Q2 역방향 차단 |
| **MSX ON + PC 연결** | **위험 — 이 하나만 피하면 됨** |

부수 이득: D2의 0.3 V 강하가 사라져 PC 급전 시 `+5V`가 4.7 → 4.95 V로 올라가고,
MSX 구동 시 VBUS도 ≈ 4.98 V로 펜드라이브 전원 마진이 가장 좋다.

부수 손실: VBUS 계통에 TVS가 없다(TVS1은 `+5V_MSX`에만 있다). D2가 담당하던
USB 입력 오접속·역극성 보호가 없어진다.

**단, 이 보드는 공개 배포 예정이다.** 규율은 본인은 지켜도 남은 못 지킨다.
개인 시험기에서 마진 확인용으로는 0 Ω을 쓰되, **배포 리비전에는 넣지 말 것.**

#### 드롭이 정말 문제라면

- 저Vf 쇼트키로 교체 — PMEG2010AEH 등 Vf ≈ 0.25 V @0.5 A (SOD-323, D2 패드 호환)
- 그래도 부족하면 0 Ω이 아니라 **8절의 로드스위치**로 간다.
  AP2151/TPS2065 계열은 Rds(on) 수십 mΩ으로 드롭이 사실상 없고,
  **디스에이블 시 역전류 차단**이 내장되어 0 Ω의 문제가 원천적으로 없다.

### 7.4 부작용 — Q3/Q4 VBUS 검출이 무력화된다 (두 개조 공통)

#### 현재 회로

```
/VBUS ──[10k 내장]── Q3 DTC114EUA (E=GND)
                        └ C ── Net-(Q3-OUT) ──┬── R40 10k ── +3V3
                                              ├── C12
                                              └── Q4.G  (SSM3J332R, S=+3V3)
                                                    └ D ── SW1.3

SW1 (SK-12D02, SPDT, 공통 = 2번)
   1-2 : ESP_POW ← +3V3 직결        → ESP 상시 ON
   2-3 : ESP_POW ← Q4 드레인        → VBUS 있을 때만 ON
```

| VBUS | Q3 | Q4.G | Q4 | SW1 2-3 위치에서의 ESP |
|---|---|---|---|---|
| 없음 | OFF | R40으로 +3V3 풀업, Vgs=0 | OFF | **OFF** |
| 있음 | ON | GND | ON | ON |

#### 개조 후

역방향 쇼트키를 넣든 0 Ω으로 바꾸든, **MSX 전원만으로도 /VBUS에 4.5~5.0 V가
상시 인가**된다. Q3는 이것을 "PC 연결됨"으로 읽는다.

```
Q3 상시 ON → Q4 상시 ON → SW1 2-3 위치가 1-2 위치와 완전히 동일
```

즉 기능이 "죽는" 것이 아니라 **"상시 ON으로 고착"**된다. ESP-01은 계속 잘 돈다.
Q3 베이스 전류는 (4.55−0.7)/10k ≈ 0.39 mA로 무시 가능하다.

**진짜 손실은 다른 쪽이다 — ESP를 끌 수단이 사라진다.**
SW1 2-3은 실질적으로 "MSX 단독 구동 시 ESP OFF" 위치였고(ESP TX 피크 350 mA를
MSX 5 V에서 빼지 않는 용도), 개조 후에는 두 위치 모두 ON이 되어 OFF 자리가 없다.

#### ESP OFF 자리를 살리고 싶다면 (rev 1.3 추가 개조, 패턴 1컷)

`SW1.3 ↔ Q4.3` 패턴을 끊고 SW1.3을 개방으로 둔다.

```
1-2 : ESP_POW ← +3V3   → ESP ON
2-3 : 개방              → ESP OFF   (수동 스위치로 환원)
```

Q3 / Q4 / R40 / C12는 미사용이 되므로 그대로 두거나 제거한다.
자동 검출은 잃지만 **수동 ON/OFF라는 더 유용한 기능이 남는다.**
rev 1.4에서는 Q3-OUT을 U1 GPIO로 올리고 ESP 전원도 GPIO 제어 로드스위치로
바꾸는 것이 정답이다(8.2절).

### 7.5 개조 없이 확인만 하려면

VBUS를 외부에서 공급하는 **셀프파워 USB 허브**를 물리면 데이터만 J5로 흐르므로
인식된다. 이것이 성립하면 진단이 최종 확정된다.

## 8. rev 1.4 정식 설계

### 8.1 VBUS 전원 스위치

```
+5V ──[ USB 호스트 파워 스위치 ]── /VBUS
        예: AP2151, TPS2065, MIC2005
        · 내장 전류제한 0.5 A + 열차단 + 역전류 차단
        · EN → U1 여유 GPIO
        · /FLG → U1 GPIO (선택, 과전류 보고)
```

- 펌웨어가 **Sunrise USB 모드일 때만** EN을 어서트
- USB 디바이스 모드(BOOTSEL 업로드, CDC 디버그)에서는 EN을 반드시 디어서트

### 8.2 VBUS 검출을 GPIO로 올릴 것

현재 `Net-(Q3-OUT)`은 Q4 게이트로만 간다. 이것을 U1 GPIO로도 끌어와서
펌웨어가 **"PC에 연결되어 있는가"를 부팅 시 판정한 뒤** VBUS 스위치를 켜도록 한다.

> 주의: Q3 검출 출력으로 VBUS 스위치를 **직접** 구동하면 안 된다.
> 스위치가 켜지는 순간 Q3가 자기 출력을 다시 감지해 꺼지는 발진 루프가 된다.
> 반드시 펌웨어가 한 번 판정하고 래치하는 구조로 갈 것.

### 8.3 CC 구성

호스트로 쓸 때는 Rp가 필요하다. 완전한 DRP를 원하면 CC 저항을 아날로그 스위치로
전환하거나 TCPC를 쓰는 것이 정석이지만, 이 용도에서는 과하다.
USB2 데이터만 쓰므로 **Rd 고정(현행) 유지 + VBUS는 8.1의 스위치로 공급**이면
실사용에 충분하다. 다만 "USB-C 규격 준수"를 문서에 적지는 말 것.

### 8.4 전류 예산

MSX 슬롯 +5 V는 기기에 따라 300~500 mA 수준이 현실적 한계다.
펜드라이브 200~300 mA + 카트리지 자체 소비를 더하면 여유가 크지 않다.
전류제한 0.5 A 스위치가 적절하며, HDD형 장치는 지원 대상에서 제외한다.

## 11. rev 1.4 적용 결과

### 11.1 실제로 바꾼 것

| 부품 | 처리 |
|---|---|
| **D2** B5819WS | 삭제 — VBUS 역류 차단 다이오드 |
| **SW1** SK-12D02 | 삭제 — ESP 전원 선택 스위치 |
| **Q3** DTC114EUA | 삭제 — VBUS 검출 |
| **Q4** SSM3J332R | 삭제 — ESP 전원 스위치 P-FET |
| **R40** 10k / **C12** 0.1µF | 삭제 — Q4 게이트 회로 |

§7.3 에서 검토한 "D2 를 0 Ω 으로" 와 전기적으로 동일한 결과다.
부품을 0 Ω 으로 바꾸는 대신 아예 제거하고 F1 만 남겼다.

### 11.2 rev 1.4 의 VBUS 경로 (실측 넷리스트)

```
/VBUS  :  J5.A4  J5.A9  J5.B4  J5.B9   C27.2  C28.2  F1.1
/+5V   :  F1.2  IC1.2  IC1.3  Q1.6  Q2.2  U1.34  C1.1 C4.1 C5.1 C6.1 C7.1 …
```

```
MSX +5V ──Q1/Q2 오링── +5V ──F1(FSMD075)── /VBUS ── J5 ── USB 메모리
```

- **F1 이 유일한 직렬 소자**다. 홀드 0.75 A / 트립 1.5 A 가 곧 USB 호스트 전류 제한이 된다.
- VBUS 전압 ≈ MSX 5 V − F1 저항 강하. 0.3 A 에서 약 0.07 V 이므로 **4.9 V 내외**.
  §7.1 의 쇼트키 안(4.55 V)보다 마진이 좋다.
- **F1 을 0 Ω 점퍼로 대체하면 USB 호스트 전류 제한이 사라진다.** BOM 에 ★★ 로 표기했다.

### 11.3 ESP-01 전원

```
rev 1.3 :  +3V3 ─┬─ SW1.1 ─┐
                 │         ├─ SW1.2 ─ ESP_POW ─ J2.8
           Q4 ── SW1.3 ─┘      (Q3 가 VBUS 를 검출해 Q4 를 구동)

rev 1.4 :  +3V3 ────────────────────── J2.8        (상시)
```

부수 효과 두 가지.

1. **§7.4 에서 지적한 오진 요인이 사라졌다.** 1.3 에서는 풀업 상단이 `+3V3`(상시),
   J2.8 이 `ESP_POW`(스위칭)로 레일이 달라서, ESP 에 전원이 없어도 J2.4/5/6 에서
   3.3 V 가 측정됐다. 1.4 는 같은 레일이므로 이 현상이 없다.
2. **ESP 를 끌 수단이 없어졌다.** 보드에 전원이 들어오면 ESP-01 도 항상 켜진다.
   아이들 ~70 mA 가 부담되면 CH_PD(GP44) 또는 RST(GP42) 를 펌웨어에서 Low 로
   내리는 하드 파워다운(~20 µA)을 써야 한다. → `ESP01_BRINGUP.md` §7(4)
   (이 때문에 1.3 에서 "GP44 연결 삭제 권장" 이라고 쓴 판단을 **철회**했다.)

### 11.4 남은 제약 — 반드시 지켜야 할 운용 규칙

**MSX 에 카트리지를 꽂은 상태에서 PC 에 USB 케이블을 연결하지 말 것.**

D2 가 없으므로 §7.3 의 표가 그대로 적용된다.

| 조합 | 결과 |
|---|---|
| MSX ON + PC 미연결 | 안전 (의도한 동작. USB 메모리 급전됨) |
| 카트리지 미장착 + PC 연결 | 안전 — Q2 바디다이오드가 PC→MSX 를 막는다 |
| MSX 장착·전원 OFF + PC 연결 | 안전 — `+5V_MSX` = 0 V |
| **MSX ON + PC 연결** | **MSX 5 V 가 PC VBUS 로 역류. 금지** |

펌웨어 업로드(BOOTSEL)는 **카트리지를 MSX 에서 뺀 뒤** 한다.
이 규칙은 BOM 조립 주의사항과 `JLCPCB_ORDER.md` §4.3 에도 적기했다.

부수 손실도 그대로다 — **VBUS 계통에 보호 소자가 없다.**
TVS1 은 `+5V_MSX` 진입점에만 있고 VBUS 에는 C27/C28 뿐이다.

### 11.5 공개 배포 시 고려

이 구성은 "규율에 의존하는 안전"이다. 본인은 지켜도 남은 못 지킨다.
배포를 전제로 한다면 rev 1.5 에서 §8 의 정식안으로 가는 것이 맞다.

```
+5V ──[ AP2151 / TPS2065 / MIC2005 ]── /VBUS
        · 내장 전류제한 0.5 A + 열차단 + 역전류 차단
        · EN → U1 여유 GPIO (Sunrise USB 모드에서만 어서트)
        · VBUS 검출을 U1 GPIO 로 올려 부팅 시 1회 판정 후 래치
```

로드스위치는 **디스에이블 시 역전류를 차단**하므로 11.4 의 운용 규칙 자체가 없어진다.
