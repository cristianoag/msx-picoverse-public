## 0. 목표와 범위

기존 MSX 카트리지 상판/하판 셸을 **편집 가능한 파라메트릭 솔리드**로 재현한다.
현재 `V1.3.FCStd` 안의 셸은 STL 메시라 치수 수정이 불가능하다.

| 항목 | 내용 |
|---|---|
| 제작 방식 | **3D 프린팅 (FDM / SLA)** |
| 목표 | 기존 셸 **충실 재현** |
| 이번 범위 밖 | USB-C · BOOTSEL 버튼 · 슬라이드 스위치 · microSD 개구부 — 재현 완료 후 별도 단계 |

3D 프린팅이 전제이므로 **구배각·게이트·이젠핀은 모델링하지 않는다.** 균일 벽두께와
프린터 공차만 고려한다.

## 2. 좌표 기준 — 가장 먼저 고정할 것

모든 모델은 **PCB 원점**을 기준으로 만든다. PCB 원점은 골드핑거(슬롯엣지) 중심선이다.

```
KiCad X =  DXF X − 131.4896
KiCad Y = −(DXF Y − 92.3440)      ← KiCad 는 Y 아래가 +, DXF 는 Y 위가 +

FreeCAD 모델 좌표 (Y 위가 +) 로 쓸 때는
  model X =  DXF X − 131.4896
  model Y =  DXF Y − 92.3440
  model Z =  기판 상면 = 0  (Z 는 메시 실측으로 결정)
```

### 검증 기준값 (이 값이 안 나오면 좌표가 틀린 것)

| 대상 | KiCad 좌표 | 모델 좌표 (Y 부호 반대) |
|---|---|---|
| 마운팅홀 좌 (Ø4.5) | (−28.15, −21.20) | (−28.15, +21.20) |
| 마운팅홀 우 (Ø4.5) | (+27.85, −16.00) | (+27.85, +16.00) |
| 홀 간격 | dx 56.000 / dy 5.200 | 동일 |
| 카트리지 셸 중심선 | x = −4.950 | 동일 |
| PCB 슬롯엣지 중심선 | x = 0.000 | 동일 |

**PCB 중심선과 카트리지 중심선은 4.950 mm 어긋나 있다.** 이 값을 놓치면 셸 전체가
5 mm 밀린다. DXF 도면의 치수 문자(28.2 / 27.9)는 소수점 1자리로 반올림된 값이므로
**치수 문자를 믿지 말고 도형의 실제 좌표를 쓸 것.**

## 3. DXF에서 이미 확인된 치수

에이전트가 다시 재보되, 아래와 어긋나면 좌표계를 의심할 것.

### 셸 외곽 (KiCad X 기준, 모두 x = −4.950 대칭)

| 윤곽 | 좌 | 우 | 폭 |
|---|---|---|---|
| 최외곽 | −59.442 | +49.542 | 108.984 |
| 2번째 | −58.950 | +49.050 | 108.000 |
| 3번째 | −58.050 | +48.150 | 106.200 |
| 최내곽 | −57.176 | +47.276 | 104.452 |

세로 방향 — **rev2 정정**. 초판의 65.2는 오독이었다. 65.2는 PCB 기준선(y=0)에서
안쪽 윤곽(y = −65.200, 폭 102.70)까지의 치수이며 셸 외곽이 아니다.
DXF 수평선을 전수 조사한 실제 외곽:

| 위치 | KiCad y | 비고 |
|---|---|---|
| 최상단 모서리 테이퍼 | −68.392 | x −55.450~−44.950 / 36.050~45.550 |
| 상단면 | −67.900 | 폭 101.000 |
| 안쪽 윤곽 | −65.200 | 폭 102.700 ← 도면의 65.2 치수가 가리키는 선 |
| 하단(슬롯쪽) | +1.000 | 외곽 모서리 +0.996, 슬롯 립 +0.945 |

**셸 전체 길이 = 69.392 mm.** 메시 실측 69.4~69.5와 일치한다.
셸은 측면 108.984 폭에서 상단으로 갈수록 101.000 까지 좁아지는 테이퍼 형상이다.

### 기타

| 항목 | 값 |
|---|---|
| 마운팅홀 | Ø4.5 × 2 |
| 나사 | `2 - FH, Ø2.7 × 12 mm (14 mm)` — 접시머리 |
| 라벨 영역 | 81.0 (W) — 도면 주기의 높이값은 셸 높이와 모순되므로 **메시로 재확인** |
| PCB 외형 | 101.15 × 66.05, KiCad x −54.000 ~ +47.150 |
| PCB 우측 여유 | **rev2 정정** — DXF 최내곽(+47.276) 기준 0.126 여유였으나, 하판 메시 실측 내벽은 +46.974 라 **0.176 겹침**. 메시를 채택한다 (아래 참조) |
| PCB 좌측 | −54.000, 셸 기준선 −53.996 과 0.004 일치 → **좌측이 기준면** |

### DXF 파싱 시 주의

- 도면은 **평면도 2개**(상판·하판)와 주기 영역으로 구성된다. 단면도·측면도가 없어
  **Z 정보가 전혀 없다.** Z는 전부 메시 실측으로 얻는다.
- `DIMENSION`(15) · `MTEXT`(22) · `SOLID`(38, 화살촉) · `LEADER`(3) · `HATCH`(3) 은
  전부 **주석이므로 제외**한다.
- `ELLIPSE` 17개는 장단축비가 0.0087 / 0.0349인 **퇴화 타원**이다. 사실상 선분이므로
  직선으로 근사하거나 무시해도 된다. 프로파일 폐곡선을 만들 때 이것 때문에
  갭이 생기면 `Draft → Upgrade` 로 병합한다.
- `SPLINE` 8개는 주기 영역의 지시선이다. 프로파일에는 쓰이지 않는다.

### S1. 기존 메시에서 Z 치수 실측 ★ 이 단계가 전체의 성패를 가른다

DXF에 없는 모든 Z 정보를 여기서 뽑는다.

**작업**
1. `V1.3.FCStd` 를 **읽기 전용으로 별도 오픈**하고 두 메시의 바운딩박스를 얻는다

```python
import FreeCAD as App
doc = App.openDocument(r"<...>/3D MODEL/V1.3.FCStd")
for name in ("RevC_BOTTOM_MSXCART__KONAMIType", "splider_flash_top"):
    o = doc.getObject(name)
    bb = o.Mesh.BoundBox
    print(name, o.Placement)
    print("  X %.3f..%.3f  Y %.3f..%.3f  Z %.3f..%.3f"
          % (bb.XMin, bb.XMax, bb.YMin, bb.YMax, bb.ZMin, bb.ZMax))
    print("  facets", o.Mesh.CountFacets)
```

2. **메시가 PCB 원점과 같은 좌표계인지 먼저 확인한다.** 바운딩박스 폭이 약 109,
   높이가 약 65.2 로 나오고 X 중심이 −4.95 근처면 정렬되어 있는 것이다.
   아니면 2장 변환식으로 맞춘 뒤 진행한다.

3. 각 메시를 평면으로 잘라 단면을 뽑고, 아래 값을 실측한다.

```python
import Mesh, Part
# 예: 하판을 y = -30 (모델좌표 +30) 평면으로 절단해 벽 단면을 본다
sect = o.Mesh.crossSections([((0, 30, 0), (0, 1, 0))], 0.0)
for poly in sect[0]:
    pts = [(round(p.x,3), round(p.z,3)) for p in poly]
    print(len(pts), pts[:12])
```

**실측할 항목** — 상판·하판 각각

| 파라미터 | 설명 | 측정 방법 |
|---|---|---|
| `shell_h` | 셸 높이 (합체면 → 바깥면) | 바운딩박스 Z 범위 |
| `wall_t` | 측벽 두께 | 측벽을 가로지르는 단면에서 내외 간격 |
| `top_t` | 상/하면 판 두께 | 중앙부 수직 단면 |
| `pcb_slot_z` | PCB가 앉는 높이 | PCB 지지 리브 상면 Z |
| `pcb_slot_t` | PCB 슬롯 폭 | 1.6 + 여유 |
| `boss_od` | 나사 보스 외경 | 홀 중심 주변 단면 |
| `boss_h` | 보스 높이 | 동상 |
| `boss_id` | 보스 하부 나사 구멍 | Ø2.7 계열 확인 |
| `corner_r` | 모서리 라운드 | 평면 단면 |
| `rib_*` | 내부 리브 위치·두께 | 평면 단면 여러 장 |
| `slot_open_w` | 카트리지 하단 슬롯 개구부 | 하단 단면 |

**검증**
- 상판 `shell_h` + 하판 `shell_h` 가 실물 카트리지 두께(대략 10~13 mm)와 맞는가
- 두 메시의 XY 바운딩박스가 3장의 셸 외곽(108.984 × 65.2)과 ±0.5 mm 안에 드는가
- `boss` 중심이 2장 검증 기준값(−28.15, +21.20) / (+27.85, +16.00) 에 오는가

**산출물** — `doc/case_measured_params.md` 에 측정표를 기록한다.
이후 단계는 **이 표만 참조**하고 메시는 다시 건드리지 않는다.

> 메시를 `Part::Shape` 로 변환(Shape from mesh)하지 말 것. 면 수가 많아 실패하거나
> 쓸 수 없는 솔리드가 나온다. 메시는 **자로만** 쓴다.

## 5. MCP 사용 지침 (함정)

1. **새 문서에서 작업한다.** `V1.3.FCStd` 는 오브젝트 1716개다. 여기서 작업하면
   매 recompute 가 수십 초씩 걸린다.
2. **`execute_code` 를 주력으로 쓴다.** 개별 오브젝트 생성 툴을 여러 번 호출하는 것보다
   파이썬 블록 하나로 묶는 편이 왕복이 줄어 훨씬 빠르고 안정적이다.
3. **한 블록에서 너무 많이 하지 않는다.** 실패 시 어디서 깨졌는지 알 수 없다.
   S1~S7 각 단계 안에서도 검증 가능한 단위로 쪼갠다.
4. **모든 코드 블록 끝에 `doc.recompute()` 와 검증 출력을 넣는다.** 값이 돌아오지 않으면
   성공 여부를 알 수 없다.
5. **메시는 측정 전용.** 솔리드로 변환하려 들지 않는다.
6. **좌표는 매 단계 검증한다.** 2장의 홀 좌표 두 개가 가장 빠른 확인 수단이다.
7. **파일 저장 전 KiCad 관련 파일이 열려 있지 않은지 확인** — 이 프로젝트는 lock 파일
   (`~*.lck`) 이 있으면 다른 도구가 쓰고 있다는 뜻이다.

## 7-1. rev2 확정 사항 (S1 결과 반영)

### (1) 셸 길이 — 69.392 채택

DXF와 메시가 일치한다. 초판의 65.2는 폐기. `shell_l = 69.392`.

### (2) 내벽 치수 — 하판 메시 채택

| | 좌 | 우 | 내부 폭 |
|---|---|---|---|
| DXF 최내곽 윤곽 | −57.176 | +47.276 | 104.452 |
| 하판 메시 실측 | −57.026 | +46.974 | 104.000 |

DXF의 최내곽 윤곽은 내벽이 아니라 다른 형상선(립 또는 금형선)으로 보인다.
**실물 메시를 채택**한다. 결과적으로 PCB 우측(+47.150)이 내벽과 **0.176 겹친다.**

이는 오류가 아니라 **의도된 타이트 설계**다. USB 노출면이라 크게 만들어 두고
줄로 갈아 맞추는 방침이며, 우측 가장자리 동박은 외곽에서 0.300 떨어져 있어
0.176 가공은 동박에 닿지 않는다. **PCB 수정 없음. 기록만 남긴다.**

### (3) 상판 메시 — 짝 여부부터 검증할 것 ★

상판·하판 메시가 **같은 카트리지의 짝이 아닐 가능성**이 있다.

| | 하판 `RevC_BOTTOM_MSXCART__KONAMIType` | 상판 `splider_flash_top` |
|---|---|---|
| 셸 높이 | 11.650 | 8.400 |
| 측벽 두께 | 2.500 | 2.400 |
| 판 두께 | 1.800 | 2.400 |
| 내부 폭 | 104.000 | 104.200 |
| 나사 홀 | 보스 확인됨 | **홀 미검출** |

이름부터 출처가 다르다(KONAMI type / spider-flash). S2로 넘어가기 전에 아래를 수행한다.

**검증 A — 립 정합** (가장 결정적)
합체 평면에서 하판 립의 **내경**과 상판 립의 **외경**을 잰다.
정상적인 짝이면 편측 0.05~0.20 유격이 나온다. 간섭하거나 0.5 이상 벌어지면 짝이 아니다.

**검증 B — 상판 나사 위치 탐침**
수직 광선 하나로 판단하지 말 것. 홀 중심 (−28.15, 21.20) / (+27.85, 16.00) 주위를
±3 mm 범위에서 0.25 mm 격자로 수직 스캔하여 재료가 얇아지는 지점을 찾는다.
동시에 **수평 광선**으로 천정 안쪽에 보스가 있는지 확인한다.

```python
# 상판 내부에서 보스 탐색 : 천정 아래를 수평으로 훑는다
for z in [ceil_z - d for d in (1.0, 2.0, 3.0, 4.0)]:
    hits = mesh.foraminate(App.Vector(-70, y0, z), App.Vector(1, 0, 0))
    print(z, sorted(h.x for h in hits))
```

**판정**
- 검증 A·B 모두 통과 → 짝이다. 상판 메시를 Z 기준으로 계속 사용.
- 하나라도 실패 → **상판 메시를 Z 기준에서 제외**한다. 상판은 하판의 립 형상과
  DXF 프로파일로부터 역산하고, 두께·높이는 실물 실측으로 채운다.

### (4) U2 간섭 — 설계 판단 필요 ★★★

`UDA1334MOD.step` 을 실측했다.

| 구성 | Z 범위 | 높이 |
|---|---|---|
| 모듈 PCB | 6.000 ~ 7.600 | 1.600 |
| 핀헤더 플라스틱 | 3.460 ~ 6.000 | 2.540 |
| 3.5 mm 오디오 잭 | 1.000 ~ 6.000 | 5.000 |
| 47 µF 전해 ×2 | 0.600 ~ 6.000 | 5.400 |
| **실장면 기준 총 높이** | | **7.600** |

U2는 B면 실장이므로 기판 하면에서 **7.600 mm** 내려온다.
하판이 주는 공간은 **1.500 mm** — **6.100 mm 간섭.**

핀헤더 스페이서를 제거해 밀착시켜도 (모듈 PCB 1.6 + 최고 부품 5.4) **약 7.0 mm**가
필요하다. **현재 하판으로는 어떤 조립 방법으로도 U2가 들어가지 않는다.**

한편 PCB 상면 위로는 **10.352 mm** 여유가 있다. 즉 공간은 있는데 반대쪽에 있다.
S5까지 미루지 말고 지금 아래를 확정할 것.

1. 카트리지 안에서 **PCB의 어느 면이 하판 바닥을 향하는가** — MSX 슬롯 A/B면과
   골드핑거 핀 번호로 결정된다. B면이 상판을 향한다면 U2는 여유 2.75 로 들어간다.
2. 1번이 불가하면 선택지는 셋이다.
   - U2를 F면으로 이설 (PCB 재배치·재배선)
   - 하판 바닥에 U2 자리만큼 국부 함몰/개구 추가 (셸 충실 재현에서 벗어남)
   - 오디오 잭 없는 저배 DAC 모듈로 변경
